# 전체 서비스 수동 테스트

2026-11-01에는 HDR 사진 test7.jpg로 실제 유료 전체 흐름도 검증했다.
학습지·생성 2번의 결과는 [test7 실제 검증 기록](실제서비스-test7-검증.md)에 별도로 정리했다.
아래 학습지 1번 기록은 이전 testdata.jpg 실행이며, 서로 다른 두 테스트를 보존한다.

## 준비된 파일

| 파일 | 역할 |
|---|---|
| `.run/AUTEDI_Local_Fixed.run.xml` | 로컬 DB·고정 AI 응답용 IntelliJ 실행 설정 |
| `.run/AUTEDI_Local_Terra.run.xml` | 로컬 DB·실제 Terra용 실행 설정 |
| `http/service-flow.http` | 로그인부터 교사 수정·삭제·복원까지 단계별 요청 |
| `http/http-client.env.json` | 로컬 주소·샘플 이미지 경로·교사 편집 문구 |
| `http/http-client.private.env.json` | 로컬 로그인 정보와 이번 테스트 ID. Git 제외, 값 출력 금지 |
| `scripts/local_service_smoke.py` | 승인된 생성 한 건만 실행하고 결과를 남기는 로컬 검증 도구 |
| `build/manual-service-test/` | 이번 실행의 접수 기록·편집 전후 검토 JSON·보정 PNG |

기존 `.env`와 IntelliJ의 `AutediApplication` 설정은 수정하지 않았다. 새 `.run` 설정은 Java 21 프로젝트 SDK와 `autedi.main` 모듈을 사용하며, 작업 폴더는 프로젝트 루트다.

## IntelliJ에서 실행

1. `.env`의 `LOCAL_DB_URL`이 별도 로컬 DB `autedi_ai_local`을 가리키는지 확인한다. DB 사용자·암호·API 키는 공개 파일에 복사하지 않는다.
2. 이미 실행 중인 서버가 있다면 유지해서 사용한다. 새 설정으로 전환할 때만 기존 실행을 중지하고 상단 실행 목록에서 `AUTEDI Local - FIXED` 또는 `AUTEDI Local - TERRA (paid)`를 선택한다. 두 설정은 같은 8080 포트를 사용한다.
3. 두 설정 모두 `local` 프로필과 `.env[.properties]` import를 사용한다. 기본 연결 확인은 FIXED, 실제 AI 시험은 TERRA다.
4. `http/service-flow.http`를 열고 환경을 `local`로 선택한다. 개인 로그인 정보는 이미 생성된 private 환경 파일을 사용한다. 다른 계정을 쓰려면 private 파일만 수정한다.

Spring Boot에 필요한 옵션은 실행 설정 파일에 저장되어 있으므로 Program arguments를 다시 입력할 필요가 없다. `.env`는 properties로 읽으므로 값에 따옴표나 `export`를 붙이지 않는다.

## 요청 순서

`.http` 파일은 각 블록 왼쪽의 실행 버튼으로 하나씩 실행한다. TERRA 모드에서는 생성이 유료이고 백그라운드 작업을 기다려야 하므로 `Run All`을 사용하지 않는다.

1. **01 Login**: 액세스 토큰을 HTTP Client 세션 변수에 보관한다. 토큰을 복사해 공개 파일에 저장하지 않는다.
2. **02 Upload**: `test_data/testdata.jpg`를 새 학습지로 업로드한다. 새 학습지 ID와 그 학습지의 생성 멱등키가 자동 설정된다.
3. **03 Settings**: 문법 Standard·내용 Advanced를 저장한다.
4. **04 Generate**: 작업을 접수한다. TERRA의 정상 새 생성은 전사 1회·첨삭 1회의 유료 요청이다. 같은 블록을 같은 키로 재전송하면 동일 작업을 반환한다.
5. **05 Poll**: SUCCEEDED 또는 FAILED까지 이 조회만 반복한다. OCR → AI_CORRECTION → COMPLETED 단계를 확인한다. 조회는 LLM을 호출하지 않는다.
6. **06 Review**: SUCCEEDED 후 실행한다. 카드·reviewIssues·경고·모델/계약 버전과 전사 ID를 확인한다. 편집할 카드와 ETag가 자동 선택된다.
7. **07 Prepared PNG**: 화면 기준 이미지다. 좌표는 원본 사진이 아닌 이 보정 PNG 전체 기준 0~1이다.
8. **08 Reload correction** 후 **09 Teacher edit**: 현재 content만 바뀌고 최초 AI 필드가 유지되는지 자동 검사한다.
9. **10 Soft delete** → **11 Restore**: 매 응답의 최신 ETag로 삭제·복원한다. 복원하면 교사 편집 내용이 유지된다.

이번 테스트 결과만 다시 볼 때는 **01 로그인 후 05 상태 조회 또는 06 검토 조회부터** 실행하면 된다. private 환경 파일에 이번 학습지·생성·카드 ID가 저장되어 있다. 이 경로에서는 새 학습지 업로드와 유료 생성을 반복할 필요가 없다.

## 이번 실제 실행 범위

사용자가 승인한 새 학습지 한 건만 기존 IntelliJ 서버의 local/TERRA 모드에서 실행했다. 로컬 MySQL은 `autedi_ai_local`이다. 같은 생성 키 중복 접수는 같은 작업 ID를 반환했다. FAILED에 대한 추가 유료 재시도는 실행하지 않는다.

자동 검증 도구는 접수 시도 전 `build/manual-service-test/receipt.json`에 기록한다. 결과가 불확실한 접수는 자동 재전송하지 않고, 완료 기록이 있으면 새 생성 없이 종료한다. `--resume`은 기록된 작업의 조회·후속 확인용이다. 접수 기록 파일은 중복 유료 실행 방지에도 사용하므로 임의 삭제 후 재실행하지 않는다.

## 발견한 업로드 제약

`test8.jpg`, `test7.jpg`, `test6.jpg`에는 MPF/Apple HDR gain-map 보조 JPEG가 들어 있다. 당시 단일 프레임 검사에서 `FILE_004`로 거부됐으며 AI 요청은 발생하지 않았다. 단일 JPEG인 `testdata.jpg`로 본 테스트를 진행했다.
이후 [HDR 보조 이미지 처리](AI-HDR-보조이미지-처리.md)를 추가해 확인된 HDR JPEG는 기본 사진을 보정 PNG로 준비한다. 이 후속 변경으로 실제 AI 생성을 다시 실행하지는 않는다.

## 결과 확인

이번 실제 실행은 **학습지 1 / 생성 작업 1, SUCCEEDED/COMPLETED**로 성공했다. 카드 2개(REPLACE), reviewIssues 0개, 제외 0개이며, `go → went`, `yesterday → yesterday.` 제안이 저장됐다. 같은 키 재전송과 교사 편집·삭제·복원, 최초 내용·좌표 보존을 확인했다. 상세 기록은 `build/manual-service-test/result.md`에 있다.

이번 사진에서는 GUIDANCE가 생성되지 않았다. 해당 실제 결과 유형과 프론트 시각 표시는 이번 한 건에서 검증했다고 보지 않는다.

- `build/manual-service-test/receipt.json`: 작업 ID·상태 전환·검증 결과. 인증정보 없음.
- `build/manual-service-test/review-before.json`: 최초 AI 제안과 좌표·경고.
- `build/manual-service-test/review-after.json`: 교사 편집·삭제·복원 후 결과.
- `build/manual-service-test/prepared.png`: 전사·첨삭·좌표가 공유한 이미지.

전체 전사문·원본 응답 아카이브는 로컬 DB의 `worksheet_transcriptions`, `worksheet_generation_results`에서 확인한다. 예를 들어 `select id, status, current_stage, client_mode, input_transcription_id from worksheet_generations where id = 1`로 이번 작업의 실행 경로와 전사 참조를 볼 수 있다.

실제 모델이 반환한 박스의 시각적 정확도, 실제 프론트 화면, 다중 서버·부하·재시작은 이번 실제 한 건에서 추가 검증하지 않는다. 실패·재시도·동시 요청의 고정 데이터 자동 테스트는 기존 통합 테스트를 사용한다. 다음 기능 구현이나 운영 DB 적용은 진행하지 않는다.

준비 파일은 XML 2개·환경 JSON 3개·응답 핸들러 JavaScript 10개와 Python 문법을 검사했다. 완료 receipt가 있으면 새 유료 생성 없이 종료하는 보호 동작도 확인했다. 운영 코드가 바뀌지 않아 전체 Gradle 검사는 반복하지 않았으며, 직전 외부 API 없는 348건 통과 결과를 유지한다. 새 실행 설정을 IntelliJ GUI에서 직접 시작하거나 `.http` 파일을 IDE에서 실행한 것은 아니므로, 이번 정적 검사와 기존 서버에서의 실제 API 검증을 구분한다.

요청 파일의 세션 변수와 응답 검사는 [IntelliJ HTTP Client 문서](https://www.jetbrains.com/help/idea/http-client-reference.html)의 방식으로 구성했다.
