# AUTEDI AI 실험 기준 버전 — 2026-10-30

기준 ID: `A-terra-box4-2026-10-30`. 시각은 한국 시간(KST).
이 문서는 로컬 실행 로그, 저장된 결과 JSON, 이미지 위 좌표 대조 및 현재 테스트 코드를 기준으로 작성했다.
사용자가 MVP 연동 모델·방식으로 선택한 기준이며, 운영 품질이나 일반적인 모델 정확도·속도가 검증됐다는 뜻은 아니다.

## 1. 확정한 방향과 현재 범위

- 모델: 두 단계 모두 코드상 `gpt-6.1-terra`. 계정별 이용 가능 여부·가격에 대한 별도 주장은 하지 않는다.
- A 방식: 이미지 → 오류를 보존한 전사 텍스트 → 같은 이미지와 이번 전사문으로 첨삭·대상 좌표 요청.
- 정상 완료 시 API 요청 2회. 자동 재시도 없음. 전사 실패·빈 전사문이면 첨삭 요청을 보내지 않는다.
- 연속 실험에서는 EXIF/eXIf 방향을 보정한 같은 PNG를 두 단계에 전달한다.
- 첨삭 좌표는 `boxes: [[left, top, right, bottom]]`. 전체 전달 PNG 기준 0~1 값이다.
- 현재는 test 소스의 수동 main 실험이다. 운영 API·DB·작업 상태·재시도와 통합하지 않았다.
- 다음 단계는 A 백엔드 코드를 확인해 연동하고 업로드→생성→저장→조회→하이라이트를 검증하는 것이다.
- 프롬프트 일관성 강화와 추가 출력량 절감은 연동 후 별도 실험으로 진행한다.

## 2. 요청 설정과 재현 조건

| 항목 | 현재 값 |
|---|---|
| API | POST /v1/responses |
| 모델 | gpt-6.1-terra |
| 이미지 detail | high |
| max_output_tokens | 각 호출 12000 |
| 저장 옵션 | store=false |
| 출력 제약 | text.format의 json_schema, strict=true |
| reasoning effort / temperature / service tier | 요청에서 명시하지 않음 |
| 관찰된 첨삭 응답 service_tier | default |
| 연결 / 요청 타임아웃 | 20초 / 3분 |
| Java | 21 |

전사는 철자·문법·대소문자·문장부호를 고치지 않고 줄바꿈을 보존하도록 지시한다.
첨삭은 학생 오류와 OCR 불일치를 구분하고, 불명확한 원문은 needs_review로 반환하도록 지시한다.
좌표는 원본 글자를 모두 포함하는 직사각형으로 요청하며, 위치를 찾지 못하면 빈 배열과
location_uncertain=true를 반환하도록 한다. 이 지시는 모델이 항상 준수한다는 보장이 아니다.

정확한 프롬프트·스키마는 이 문서와 함께 커밋되는 TerraTextOcrExample.java와
TerraCorrectionExample.java의 instructions/SCHEMA가 기준이다. 변경 시 이 기준 ID와 구분해 기록한다.

## 4. 직접 관찰한 결과와 한계

### test8

- 22개 모두 직사각형이며 형식 검증 통과. 이미지 대조에서 대부분 대상 단어/구절 근처를 감싼다.
- 8번 she는 오른쪽 글자 일부를 놓치고, 긴 구절의 박스는 인접 줄이나 다른 박스와 일부 겹친다.
- 14번 mistake → mistake"는 전사문에 이미 닫는 따옴표가 있어 그대로 적용하면 중복된다.
- 같은 문장을 질문 또는 서술로 바꾸거나 who were를 what the/where the로 고치는 등 실행 간 판단 차이가 있다.

### test7

- 본문 박스는 대체로 대상 단어와 맞았으나 정답 박스를 이용한 정량 평가를 하지는 않았다.
- 22~24번은 사용자가 첨삭 대상이 아니라고 지정한 하단 별도 종이 영역이다. 교정 1개 + 검토 2개.
- 첫 불명확 단어는 이전 gaw → all 추측 대신 [unclear]/needs_review로 처리했다.
- sat → got은 문맥 추정이며 학생 오류인지 전사 오류인지 확정하지 않았다.
- pan cake를 pancake/pancakes로 바꾸는 등 수정 범위가 실행마다 달라진다.
- 전사된 on of it에는 이번에 교정/검토 항목이 없었다. 검출 누락 여부는 별도 평가가 필요하다.

### 해석 주의

requires_review=false는 코드 검증 경고가 없다는 뜻이다. 교정이나 이미지 위치가 정답이라는 뜻이 아니다.
수동 시각 대조는 잠정 판단이며, 정확도 100%나 일반적인 성능 우위로 인용하지 않는다.
4개 숫자는 쐐기 모양을 구조적으로 방지하지만 위치 정확도를 보장하지 않는다.
전사 API도 매번 다시 호출하므로 첨삭 입력 자체가 달라진다. 동일 전사문 반복 실험과 전체 flow 실험을 구분한다.

## 6. 실행 및 연동 전 확인

실험 코드는 `src/test/java/com/ceos24/autedi/aiexperiments/`에 모았다.
각 파일의 클래스 주석과 [실험 코드 안내](README.md)를 참고한다.

```powershell
# 실제 유료 API 총 2회
.\gradlew.bat terraFlow --args="../test_data/test8.jpg"
# API 호출 없이 입력/키 존재 여부 확인
.\gradlew.bat terraFlow --args="--check ../test_data/test8.jpg"
# API 없는 단위 테스트
.\gradlew.bat test --tests "com.ceos24.autedi.aiexperiments.*Test"
```

로컬 단위 테스트 11개는 원문 위치, 박스 숫자/범위/양수 크기, 픽셀 변환, 겹침 및 EXIF 처리를 검증한다.
의미적 첨삭 품질과 실제 위치는 검사하지 않는다. 일반 Gradle test는 유료 main을 실행하지 않는다.

연동에서는 표시 이미지와 좌표 기준 통일, 생성 중/완료/실패 상태, 부분 성공 보존 및 재시도,
원문/제안 저장, 본문 밖 영역 제외, 중복 문장부호 방지 등을 확인해야 한다.
현재 기준에는 원본 이미지 좌표 역변환, DB 저장, 제안 자동 적용, 운영 재시도가 구현돼 있지 않다.
