범위: 수동 판독 기준, Terra·Luna 비교, Terra 좌표 배열 최적화 전후 비교, MVP 적용 판단

## 1. 핵심 결과

- 기존 Terra에서 Luna로 변경: 세 요청 합계 시간이 **16.4% 감소**했지만 총 토큰은 **12.1% 증가**했다. 증가 원인은 주로 추론 토큰이었다.
- Terra의 좌표 응답을 객체 4개에서 숫자 8개 배열로 변경: 출력 토큰 **25.2% 감소**, 총 토큰 **16.1% 감소**, API 시간 **25.8% 감소**했다.
- 배열 변경 후 추론을 제외한 결과 출력량은 세 사진 모두 약 **27% 감소**했다.
- 수동 판독으로 정한 제한된 평가 구간에서 기존 Terra는 **100%**, 기존 Luna는 **96.7%**의 1−WER 점수였다. 전체 전사·좌표 정확도를 뜻하지 않는다.
- Luna에서는 bag→bug 같은 단어 오인식과 Sudenly→Suddenly 같은 원문 철자 변경이 관찰됐다.
- 배열 방식 Terra도 test7 한 장에 **90.632초**가 걸렸다. 즉시 결과를 기다리는 사용 흐름에는 추가 개선이 필요하다.
- 다음 후보는 **줄별 전사·좌표**, 그리고 비교용 **좌표 없는 전사**다. 아직 구현하거나 성능을 측정하지 않았다.

각 조건·사진당 한 번의 실행 결과를 비교했다. 평균·중앙값·P95나 통계적 유의성을 계산한 실험이 아니다.

공통적으로 원문을 교정하지 않는 전사, 단어별 좌표, 불확실 표시를 요청했다. 기존 코드에서 image detail은 high였다. Luna 파일 추가 당시에는 모델만 변경했으며 Fast와 추론 강도를 명시하지 않았다. 실제 실행 시 코드/프로젝트 설정이 추가 변경되었는지, 적용된 service_tier가 무엇인지는 로그만으로 확정할 수 없다. 이번 결과를 Luna Fast 실험으로 부르면 안 된다.

API elapsed는 프로그램에서 측정한 요청·응답 경과 시간이다. 컴파일 시간을 포함하지 않고, 서버 대기·입력 처리·추론·생성·전송 시간을 따로 분해한 값도 아니다.
토큰 감소율과 시간 감소율이 항상 비례하는 것은 아니다.

## 5. 수동 판독 기준과 오인식 평가

### 5.1 임시 정답의 성격

세 이미지를 직접 보고 만든 임시 기준이다. 독립적인 인간 검수 정답이 아니며, 모델 출력을 먼저 본 상태에서 판독하여 편향 가능성이 있다. 판독이 바뀌면 점수도 바뀐다.

- 영어 본문만 평가했다.
- 인쇄된 양식, 제목, 이름·날짜·낙서 및 test7 하단 다른 종이에 걸쳐 잘린 글은 정량 평가에서 제외했다.
- 대소문자와 따옴표·일반 문장부호를 정규화했고 아포스트로피는 유지했다.
- 줄바꿈으로 갈라진 pla/-stic 및 bookca/-se는 연결했다.
- 학생의 잘못된 철자는 그대로 보존해야 한다. droped→dropped도 전사 오류다.
- 애매한 구간은 MASK로 제외했다. test8은 bag 앞의 불명확한 철자 세 곳, test7은 It 다음 단어·부정 표현·and he 뒤 동사 세 곳이다.
- 점수 = 100 × (1 − (대체 + 누락 + 삽입) / 평가 단어 수).

MASK 정렬 방식과 정규화 본문 전문은 [수동 판독 기록](./OCR-Terra-Luna-수동비교-2026-10-29.md)에 있다.

### 5.2 기존 응답의 점수

| 사진 | 평가 단어 | 기존 Terra 오류 | 기존 Luna 오류 | 기존 Terra 점수 | 기존 Luna 점수 |
|---|---:|---:|---:|---:|---:|
| test3 | 11 | 0 | 0 | 100% | 100% |
| test8 | 80 | 0 | 4 | 100% | 95.0% |
| test7 | 148 | 0 | 4 | 100% | 97.3% |
| 합계 | 239 | 0 | 8 | 100% | 96.7% |

**이 표는 기존 객체 방식 응답의 점수다. 배열 방식 Terra의 점수로 옮겨 적으면 안 된다.**
Terra의 100%는 한정된 평가 구간에서 임시 정답과 일치했다는 뜻이다. 전체 이미지의 원문 보존율이나 좌표 정확도가 아니다. 어려운 구간을 제외했으므로 실제 서비스 난도를 충분히 반영하지 않는다.

## 6. Terra 숫자 배열 변경의 효과

### 6.1 변경 내용

기존:
```json
"polygon": [
  {"x": 0.241, "y": 0.042},
  {"x": 0.269, "y": 0.042},
  {"x": 0.269, "y": 0.059},
  {"x": 0.241, "y": 0.059}
]
```

변경:
```json
"polygon": [0.241, 0.042, 0.269, 0.042, 0.269, 0.059, 0.241, 0.059]
```

순서는 [x1,y1,x2,y2,x3,y3,x4,y4]이며 좌상단부터 시계 방향이다.
Java parsePolygon()에서 네 Point로 복원하고 기존 normalized·pixels 콘솔 형식으로 출력한다.
배열 길이, 숫자 타입, 유한값, 0~1 범위, 면적이 0인지 검증한다. 이는 모든 기하학적 오류나 실제 이미지와의 불일치를 검출하는 검증은 아니다.
기울어진 사각형의 좌표 정보는 그대로 표현할 수 있다.

콘솔의 corner1/pixels 문구는 Java가 생성한다. 콘솔 로그만 줄여서는 API 출력 토큰이 줄지 않는다.

### 6.2 사진별 감소율

| 사진 | 시간 감소 | 출력 토큰 감소 | 총 토큰 감소 | 추론 제외 출력 감소 |
|---|---:|---:|---:|---:|
| test3 | 29.7% | 11.4% | 2.2% | 26.8% |
| test8 | 24.4% | 25.8% | 16.7% | 26.9% |
| test7 | 26.0% | 26.2% | 20.0% | 27.0% |
| 합계 | 25.8% | 25.2% | 16.1% | 약 27.0% |

세 요청 합계로 54.777초, 출력 4,476토큰, 총 4,407토큰을 절약했다.
입력은 요청당 23토큰 증가했다. 배열 설명 지시문 등 요청 구성이 바뀐 영향으로 보인다.
test3에서는 추론이 304→379로 증가해 전체 출력 감소율이 작아졌지만, 추론 제외 결과 출력은 약 27% 줄었다.

반환 단어 수는 11/92/169로 그대로였다. 출력 구조 간소화의 효과를 뒷받침하지만, 단어 수가 같다고 전사 내용과 정확도가 같은 것은 아니다.

### 6.3 배열 방식에서 달라진 전사

| 사진 | 기존 Terra | 배열 Terra | 판단 |
|---|---|---|---|
| test3 | happened, | happened. | 임시 판독 기준 개선 |
| test8 | Sudenly | Suddenly | 임시 판독 기준 원문 철자 보존 실패 |
| test8 | ludry / loudry / laundry | laudry로 통일 | 원문이 애매해 정답 판정 보류 |
| test7 | practice | Pracstice | 철자 판독 변화, 재검토 대상 |
| test7 | he got | he sat | 이전에도 평가에서 제외한 애매한 구간 |
| test7 | 마지막 [unclear] | cord | 잘린 영역의 판독 변화, 정확성 미확인 |

agein, droped는 배열 방식에서도 유지됐다. bag→bug 변화도 없었다.
배열 방식의 전체 정답률은 다시 계산하지 않았다. 기존 Terra 100%를 그대로 적용하지 않는다.
반복 실행 변동과 스키마·프롬프트 변경 효과가 섞여 있으므로, 일부 전사 차이만으로 배열 방식이 품질을 떨어뜨렸다고 단정할 수 없다.

## 7. 좌표 비교와 미해결 문제

### 7.1 기존 Terra와 Luna

- test3: 두 모델이 단어 위치를 대체로 비슷하게 잡았다.
- test8: 첫 본문 줄 great의 가로 범위는 Terra 0.353~0.437, Luna 0.305~0.390이었다. 수동 확인상 Luna가 왼쪽으로 치우쳤고 Terra가 더 가까웠다.
- test7: Luna의 여러 본문 박스가 실제 단어보다 위에 배치된 것으로 보였다. dog의 Luna y 범위는 0.571~0.591이었다.
- Luna test7의 162개 중 114개 박스가 높이 0.020으로 동일했다. 개별 글자 경계보다 줄 단위 근사 박스일 가능성이 있으나, 이 규칙성만으로 오류를 확정하지 않는다.
- 기존 Terra test7 좌표는 중간이 생략되어 전체 좌표를 비교할 수 없다.

### 7.2 기존 Terra와 배열 Terra

동일 단어 번호의 네 꼭짓점에서 x 또는 y의 최대 절대 차이를 계산했다.

| 사진 | 비교 가능한 박스 | 최대 정규화 차이 |
|---|---:|---:|
| test3 | 11 | 0.008 |
| test8 | 92 | 0.024 |
| test7 | 37 | 0.024 |

이 값은 **정답과의 오차가 아니라 두 실행 사이 차이**다. 0.024는 해당 축 전체 길이의 2.4%다.
정답 박스 어노테이션을 만들지 않았으므로 IoU나 좌표 정답률은 산출하지 않았다.

### 7.3 회전 기준

별도로 확인한 test1.jpg는 저장 픽셀 4032×3024, EXIF orientation=6이었다. 화면에서 바로 세우면 3024×4032가 된다.
모델이 해석한 방향과 Java ImageIO의 가로·세로 기준이 다르면 픽셀 좌표가 어긋날 수 있다.
test1의 메타데이터 결과를 모든 사진에 자동 적용하면 안 된다. 각 입력의 회전 정보를 확인하고, 회전을 반영한 동일 이미지로 API 요청·좌표 변환·화면 표시를 통일해야 한다.
현재 배열 변경은 이 회전 문제를 해결하는 수정이 아니다.

## 8. MVP 적용 판단과 다음 실험

### 현재 판단

Terra 배열 방식은 측정상 유효한 최적화지만, test7 한 장 90.632초는 사진 업로드 후 즉시 결과를 기다리는 흐름에 부담스럽다.
이 시간은 전사·좌표 단계이며 실제 첨삭과 교사 검토를 포함한 전체 소요 시간이 아니다.
여러 장 업로드 후 비동기 처리하는 흐름은 기다림을 완화할 수 있지만 처리 비용과 시간을 없애지는 않는다.

이번 평가에서는 Terra가 학생 원문 철자 보존에 더 적합한 기준 후보였다. Luna는 더 저렴한 후보로 계속 평가할 수 있지만 품질을 동일하다고 가정하면 안 된다.
Fast는 처리 속도 옵션이고 원문 판독·좌표 정확도를 해결하는 설정은 아니다. low는 추론량에 영향을 줄 수 있으나 출력해야 하는 좌표 수를 줄이지 않는다.

### 우선 실험: 줄별 전사·좌표

test7의 약 23줄을 기준으로 단어 169개 대신 줄별 객체를 반환하면 좌표 숫자는 1,352개에서 약 184개로 줄어든다. 약 86% 감소는 좌표 숫자 개수 기준이며 전체 토큰·시간 감소율 예측이 아니다.

```json
{
  "lines": [
    {
      "id": 1,
      "text": "학생이 쓴 원문 한 줄",
      "polygon": [0.1, 0.16, 0.9, 0.16, 0.9, 0.19, 0.1, 0.19],
      "uncertain": false
    }
  ]
}
```

lines[].text를 백엔드에서 조립해 전체 원문을 만들면 전체 text와 words[].text의 중복도 제거할 수 있다.
첨삭은 line_id 및 원문 내 위치와 연결하고, 화면에서는 해당 줄을 강조하는 형태를 검토한다. 단어별 정밀 강조 기능을 줄 단위로 바꾸는 제품 결정이므로 교사 사용성 확인이 필요하다.

같은 이미지, 같은 모델·추론·서비스 티어 조건으로 한 요소씩 변경한다.
대표 사진에서 초기 차이를 확인한 후 반복 실행하여 중앙값과 느린 요청의 분포를 확인한다.
수집 항목은 입력/출력/추론/캐시 토큰, API 시간, 실제 service_tier, 완료 상태, 전사 오류, 좌표 오차, 재시도 및 교사 검토 시간이다.
새 API 실험의 정확한 시간 단축률은 측정 전 확정하지 않는다.
